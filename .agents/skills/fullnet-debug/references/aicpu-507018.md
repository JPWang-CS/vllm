# Pangu 启动时 AICPU 507018 的分层排查

507018 是 AICPU 执行异常总类。先从当前 run 的原始日志找第一个设备错误、kernel/so/function、rank、逻辑/物理设备、stream/task 与时间，再判断加载、参数、越界、挂起或超时。仅看顶层数字不能归因为超时或 vendor bug。

## 固定检查顺序

1. 读取当前冻结配置、实际 argv/env、模型入口、state、validation、真实进程与退出；历史同名报告先核日期。标为 P/D mixed 的配置可能尚未运行混合请求，在初始化就失败时，应写“该配置启动失败”，保留 mixed probe 为 `not_run`。
2. 对照同机近期成功记录，逐项比较真实 SDK/HCCL/AICPU 包、Python、import 顺序与最终库来源、设备映射、TP/DP/EP、graph、MTP、aligned decode、batch 与并发。成功的普通 TP2 推理可反证“TP2 全局不支持”，但不能代替 P/D 混合验证。
3. 分开通信组初始化、Host kernel launch 返回、设备 kernel 完成与真实 collective 数值。`KernelLaunch... Success` 只表示相应 Host 调用成功，不能独自证明设备初始化已完成。
4. 若首错是 `get kernel failed`、11003，并指向 `libccl_kernel.so` 的 `RunAicpuCommInit` 或 `RunAicpuIndOpThreadInit`，先核当前实际发送的 AICPU 包、设备 loader/依赖/符号日志和同环境成功反例。包存在、发送成功、Host ELF 含符号字符串仍不能证明设备已经成功加载。部分厂商包有前导签名/封装头，普通 tar 打不开不能直接记为包损坏。
5. 读取本任务 `ASCEND_PROCESS_LOG_PATH`、`ASCEND_WORK_PATH` 下实际 host/device 日志与异常栈。设备启动 INFO 不含失败时 dlopen/dlsym 细节时，明确记录缺少 loader 首错，不能猜成确定缺库。优先保存原件，再提出最小验证。
6. 授权范围内先用一个受资源 guard 保护的小型 collective 验证初始化；无模型、无性能、无额外 shape。保持选定 SDK、Python、原 HCCL 模式和必要 vendor 预加载顺序，核逻辑0/1到物理pair映射、健康、他人进程及余量；两rank都核数值、NaN/Inf和真实退出。通过只证明该机制当前可用，不自动关闭原模型故障。

受控入口还要在**实际执行 UID** 下验证冻结配置、输入和脚本可读。容器 root 只读检查成功不表示宿主 GLM UID 可读；若原实验文件不可读，通过已登记的只读导出面复制必要冻结字段到本任务私有副本并记录来源，不能改原文件或共享目录权限。此类首错记 `BLOCKED_FROZEN_CONFIG_UNREADABLE`，不当作 AICPU 再次失败。实际 HCCL/设备日志的 mode、算法和 kernel 初始化路径须与数值结果一起保留；只有环境变量 AI_CPU 不能证明特定设备 kernel 被调用。

## 避免无效重试

- 成功 run 也出现同一设备号转换 ERROR 时，该 ERROR 不是失败的充分条件。不能仅因物理编号不在可见逻辑范围就擅改已成功的映射方案。
- 已有毫秒级 kernel lookup 首错时，加大 timeout 不会修复缺失加载/符号。缩小 batch 同样没有通用保证；较大 batch 成功、较小 batch 失败时应保留这个反例。
- `HCCL_OP_EXPANSION_MODE` 的支持范围、默认值、资源限制和 fallback 随芯片/SDK/通信类型而变；先查当前版本。不能盲改 HOST/AIV/CCU 作为修复，也不能将模式切换后的通过当原配置通过。
- 设备忙、不健康、映射未确认或没有可读错误日志时停止当前设备路径，保留具体阻塞；不抢卡、不长等待、不换卡反复试。禁止设备 reset、共享驱动/SDK/权限修改及清理他人进程。

## 精确记录与跳过

原失败实验继续保留 `failed`。后续调度可只对**已失败且尚无新修复证据的组合**记录 `skipped` 或 `blocked`：平台/实际 SDK、host/pair、TP/DP/EP、graph、HCCL 模式、batch/seq、首失败 kernel 及证据引用必须齐全。reason 可用 `AICPU_HCCL_KERNEL_LOOKUP_FAILED_UNRESOLVED`；资源问题另用 `DEVICE_NOT_HEALTHY_IDLE`，不混为软件不支持。

禁止把整个 P/D、TP2 或一代芯片设为跳过，也不把跳过格计为通过。修改参数或更换 SDK 是新候选配置，原状态和结果不改写。恢复放行需要新的具体修复证据，以及按原目标完成的模型启动、真实 P/D 混合请求与精度检查；基础 collective 通过只放行下一步检查。
