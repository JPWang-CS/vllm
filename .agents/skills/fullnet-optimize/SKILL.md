# 整网与算子迭代

读取原生基线、冻结负载、实际 profiler 和精度协议。先确认热点位于计算、通信、Host 间隔还是资源等待，再选择一个修改并写出预期减少的成本与新增成本。

1. 优化前确认原始配置、实际加载路径、设备健康/空闲、物理逻辑映射和基线完整性。动态选卡与换卡都要求对应基线整组重测。
2. 算子变更交给独立算子仓构建，框架使用 `fullnet-replace` 验证实际命中与精度，再使用 `fullnet-profile` 采集同条件性能。系统变更保存到模型独立 `changes/`，不覆盖旧实验。
3. 固定输入、输出、batch、并发、序列长度、并行和采样次数。比较算子设备时间、通信、Host 间隔、TTFT/TPOT、吞吐、显存、请求失败和精度。
4. Profile daemon 失败或仅有 CPU trace 时，先恢复原始 task 的离线索引；没有实质设备 kernel 证据，不把优化写成性能通过。
5. 多项改动分别验证后再组合。报告收益、退化、适用范围、回退条件、样本数、原始实验位置和未验证项；未完成的新续跑保持 `incomplete`。

优化任务由项目私有 tmux 管理，只清理本任务进程和资源。不修改公共驱动/CANN，不自动 reset NPU。
