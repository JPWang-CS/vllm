# 性能分析

先获得同条件的正确性结果，再建立服务性能基线。性能结果按模型实验保存，算子替换实验引用同模型的原生实验。

服务基准使用当前引擎自带的 benchmark 工具，固定输入长度、输出长度、请求数量、并发和采样方法。保存原始结果与标准输出，报告端到端时延、TTFT、TPOT、ITL、吞吐和请求失败。

设备分析使用实际环境中的 msprof 或 torch_npu profiler。msprof 包裹应用/客户端的能力取决于服务进程启动方式；仅包裹 HTTP 客户端通常不能采到远端服务的设备 kernel。需要在服务侧启用采集或用引擎支持的 profiler 接口，核对 trace 是否包含目标进程与设备执行。

预热与正式采集分开。原生与替换保持相同 workload；原始 trace 放在 `experiments/<id>/profiles/`。查看算子调用、计算、通信和 Host 间隔，把单算子收益与整网收益分别报告。不同 A3/A5 数据用于平台分析，同平台同条件对照用于计算替换收益。

阶段结论应能回答：时间花在哪个算子或通信；修改改变了哪一步；目标算子节省多少设备时间；整网时延或吞吐改变多少；适用的形状和并行配置是什么。
